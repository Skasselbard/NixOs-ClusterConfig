# Command Reference

All commands listed here are generated by ClusterConfig during evaluation and added to the flake output. The exact set of available commands depends on which modules are loaded.

## Package Tooling

Every cluster flake also exposes the `clusterConfig` package browser/runner as
the default app:

```bash
nix run .# -- list
nix run .#clusterConfig -- show
nix run .#clusterConfig -- show example vm0 iso
nix run .#clcli -- run <cluster>.<node>.<package>
nix run .#clusterConfig -- path example vm0 iso
nix run .#clusterConfig -- build <cluster>.<node>.iso
nix run .#clusterConfig -- completions install zsh
```

`clusterConfig` is canonical, `clcli` is a shorthand app and binary alias. The
same derivation is available as `packages.<system>.clusterConfig`, so a
temporary environment works without installing it globally:

```bash
nix shell .#clusterConfig
clusterConfig list
clcli list
```

For a persistent install:

```bash
nix profile install .#clusterConfig
```

See [Package Tooling](Tooling.md) for completion setup, descriptions, XDG
configuration, and working-directory semantics. The `run` and `build` commands
are direct aliases for the generated `nix run`/`nix build` commands.

In the command patterns below:
- `<cluster>` is the cluster name (e.g., `example`)
- `<machine>` is the machine name (e.g., `vm0`)
- `<service>` is the service name (e.g., `dns`, `secrets`)

## Machine Commands

These commands are always available (provided by the core deployment module).

### Build

| Command | Description |
| --- | --- |
| `nix build .#<cluster>.<machine>.iso` | Build a bootable ISO image for the machine. Inherits network config, users, SSH keys, and locale settings from the machine configuration. |
| `nix run .#<cluster>.<machine>.build` | Build the machine's NixOS system locally with `nixos-rebuild build` (without deploying). |

### Deploy

| Command | Description |
| --- | --- |
| `nix run .#<cluster>.<machine>.deploy` | Deploy the machine's configuration to `deployment.targetHost` using `nixos-rebuild switch`. |

### Utilities

| Command | Description |
| --- | --- |
| `nix run .#<cluster>.<machine>.hardware-configuration` | Connect to the machine via SSH and print the auto-detected `hardware-configuration.nix`. |

## Nixos-Anywhere Commands

Available when the `nixos-anywhere` module is loaded (included in `default`).

| Command | Description |
| --- | --- |
| `nix run .#<cluster>.<machine>.create` | Perform a full system installation on `deployment.targetHost` using [nixos-anywhere](https://github.com/nix-community/nixos-anywhere). Runs the configured `formatScript` before installation. The target machine must be booted from the ISO. |
| `nix run .#<cluster>.<machine>.format` | Run only the configured format script on the target machine (without installing). Prompts for confirmation since this erases disk content. If `formatScript` is `null`, prints a skip message. |

### Format Script Options

The `deployment.formatScript` attribute controls disk formatting during `create`:

| Value | Behavior |
| --- | --- |
| `null` (default) | No formatting — skips the format step |
| `"disko"` | Uses the format script generated by the machine's [disko](https://github.com/nix-community/disko) configuration |
| A derivation / script | Runs the provided custom script |

## Colmena Commands

Available when the `colmena` module is loaded (included in `default`).

| Command | Description |
| --- | --- |
| `nix run .#colmena apply` | Deploy all machines across all clusters using [colmena](https://github.com/zhaofengli/colmena). |
| `nix run .#colmena apply -- --on <cluster>-<machine>` | Deploy a specific machine with colmena. |
| `nix run .#colmena <subcommand>` | Run any colmena subcommand (e.g., `build`, `apply-local`, `exec`). |

Colmena node names are qualified; `apply-local` may need `--node <cluster>-<machine>` because the local hostname remains the short machine name.

## Secret Service Commands

Available when the `secret-service` module is loaded.

| Command | Description |
| --- | --- |
| `nix run .#<cluster>.<machine>.secretsCheck` | Check the target key and declared encrypted secrets. |
| `nix run .#<cluster>.<machine>.secretsInstallKey` | Install or repair a managed target key. |
| `nix run .#<cluster>.<machine>.secretSet -- --key <user>/<secret>` | Set a declared secret from stdin. |

Secret changes are deployed as part of the normal NixOS closure. See the [secret-service guide](../src/services/secret-service/Readme.md) for the complete workflow.

## Deployment Workflow Summary

A typical deployment follows these stages:

```bash
Stage 0: Build ISO
  nix build .#<cluster>.<machine>.iso
  → Write to USB / mount in VM → Boot target machine

Stage 1: Initial Installation
  nix run .#<cluster>.<machine>.create
  → Formats drives (if configured) + installs NixOS via nixos-anywhere

Stage 2: Configuration Updates
  nix run .#<cluster>.<machine>.deploy
  → Updates the running system via nixos-rebuild switch
  or
  nix run .#colmena apply
  → Deploys all machines at once

Secret checks (if using secret-service):
  nix run .#<cluster>.<machine>.secretsCheck
```
